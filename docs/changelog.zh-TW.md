## v0.1.100 — 2026-08-10

### AI 智慧代理

- **Kiro CLI 成為一等公民的工作階段類型。** Kiro 工作階段在樹狀結構裡有自己的節點，狀態點由 Kiro 自己的生命週期 hooks 驅動，如實反映工作中與等待處理；一個回合結束會發通知；重新開啟節點會自動接回同一段對話；啟動參數、略過確認開關、經 vspawn 衍生子工作階段也都齊了——其他智慧代理已有的能力，Kiro 現在都有。VelaTerm 會把你的預設 Kiro agent 複製成自己的 `vlx-term` agent，只在副本上加一份只觀察、不干預的生命週期 hooks 再啟動它，你自己的 agent 檔案全程不動，提示詞、工具與 MCP 伺服器原樣帶過來。Kiro 沒有權限請求 hook，所以它等你核准的時候，狀態點仍然顯示為工作中。

### 修正

- **終端機裡啟動的程式不再繼承 AppImage 自己的環境（Linux）。** AppImage 的啟動器會把 `PYTHONHOME`、`PYTHONPATH`、`PERLLIB`、`QT_PLUGIN_PATH` 和 GStreamer 的外掛路徑指向套件內的暫時掛載目錄，並把套件內的目錄插到 `PATH`、`LD_LIBRARY_PATH` 的最前面。終端機會把整個環境交給它啟動的 shell，於是系統的 `python3` 跑到套件裡去找標準函式庫，根本起不來；其他動態連結的程式也會優先載入套件裡的那份函式庫，而不是系統的。現在 VelaTerm 在啟動 shell 或外部工具之前先把這些套件內路徑剝掉，你自己設定的值保持不動。`APPDIR` 與 `APPIMAGE` 仍然可見，靠它們判斷自己是不是從 AppImage 啟動的程式照樣拿得到答案。只有 AppImage 版本受影響，deb 套件、macOS 和 Windows 行為不變。

## v0.1.99 — 2026-08-09

### 終端機

- **Shift+Enter 換行，不再直接送出。** 終端機協定裡沒有「帶修飾鍵的 Enter」這種編碼，因此 Claude Code、Codex 這類智慧代理命令列收到的只是一個普通換行字元，話還沒寫完就被送了出去。現在 VelaTerm 改送 ESC+CR，與這些工具在 iTerm2 上設定按鍵對應後預期的序列一致，多行輸入終於可用——macOS 也包含在內，先前那裡根本沒有安裝自訂按鍵處理。輸入法組字期間不受影響，Enter 仍用於選字上螢幕。

### 專案與組織

- **單一工作階段的狀態可以單獨重新整理。** 在已啟用狀態篩選的窗格中，工作階段選單新增「重新整理狀態」，只依該窗格自己的條件重新判斷這一個工作階段並決定去留，其餘工作階段原地不動。此操作歸屬於選單所在的窗格，因此遞迴分割時不會誤用其他窗格的篩選條件；結果依窗格分別儲存，重新啟動後復原。
- **清除標記只需點一下。** 再次選擇已生效的表情即可取消，原先單獨列出的清除項目與分隔線隨之移除。篩選按鈕上的表情徽章也一併去掉：按鈕反白已經說明表情篩選處於啟用狀態，具體是哪個表情選單裡寫著。

### 修正

- **Linux AppImage 的桌面整合在任何機器上都能安裝。** 打包進去的圖示是一個指向建置機器絕對路徑的符號連結，因此 Gear Lever、AppImageLauncher 這類工具無法擷取圖示，儘管程式本身執行正常。現在改為相對連結。glibc 需求也更正為 2.35——先前只測了主程式，未計入隨套件散布的函式庫——因此桌面版支援的最舊發行版為 Ubuntu 22.04。

## v0.1.98 — 2026-08-02

### AI 智慧代理

- **Grok Build 成為 VelaTerm 的一等智慧代理。** 現在可以安裝、啟動與續接 Grok 4.5；穩定的工作階段 ID、官方 lifecycle hooks、準確的工作與權限狀態、合併後的轉錄、用量詳情，以及會隨主題變化的官方圖示，在桌面、瀏覽器與行動版檢視中保持一致。

### 專案與組織

- **將專案左欄分割成彼此獨立的工作檢視。** 任一樹狀窗格都能繼續向下分割，並在重新啟動後恢復各自的搜尋、狀態與表情篩選、摺疊狀態和分隔比例。所有窗格仍是同一份後端專案樹的投影，編輯會同步生效，不會複製業務資料。
- **標記與篩選節點時不再遺失上下文。** 專案、群組和工作階段都可以加入表情標記。命中標記的容器會保留完整子樹；狀態成員在操作期間保持穩定，同時支援動態加入和手動重新整理；狀態與表情條件以聯集方式合併。
- **直接建立空專案。** 選擇父目錄並驗證名稱後，即可在同一流程中建立並匯入資料夾。中途匯入失敗時只會重試匯入，不會重複建立目錄。

### 介面

- **在社群常用的平台分享 VelaTerm。** 分享視窗現在支援微信朋友圈、微博、小紅書、X、Reddit、Hacker News、LinkedIn、Facebook、Telegram 和 WhatsApp；微信提供 QR Code 流程，更新視窗中也新增了分享提示。
- **細節互動更順手。** 暫存終端分頁在儲存為正式工作階段前即可重新命名；一般輸入欄位會關閉行動鍵盤的自動首字母大寫，同時不改變終端輸入行為。

## v0.1.97 — 2026-07-25

### AI 智慧代理

- **工作階段不會再卡在「工作中」。** Codex 透過各自獨立的短命行程回報工具活動與回合結束，回呼抵達的先後可能顛倒，導致已經結束的回合仍顯示為工作中。現在會捨棄在自身回合結束之後才抵達的中途回報，並新增工作階段結束 hook，涵蓋未發出完成事件就退出的工作階段。
- **被中斷的回合幾秒內即可恢復正常。** 按下 Esc 或遇到串流錯誤時，Claude 與 Codex 的回合結束時完全不會發出完成回呼。現在終端連續靜默六秒後會安靜地把這類工作階段校正為等待中，且不會彈出「已回覆」通知。

### 介面

- **macOS 上的分割快速鍵更可靠。** 向右分割（Cmd+D）與向下分割（Cmd+Shift+D）現在同時註冊為原生 Terminal 選單命令，macOS 不會再在 VelaTerm 收到之前攔截這組按鍵。
- **一次按鍵只儲存一次文件。** Cmd+S 先前會被全域快速鍵與聚焦中的編輯器同時處理，可能在一次按鍵中把同一個檔案寫入兩次。

## v0.1.96 — 2026-07-23

### AI 智慧代理

- **Codex 狀態只信任 lifecycle hooks，不再依賴終端猜測。** 新版 Codex 工作階段現在只使用官方 lifecycle hooks 作為活動狀態來源。`SessionStart` 握手會驗證回呼鏈路；缺少回呼時明確顯示「狀態無法取得」；終端文字或輸出活動也不會再覆寫工作、待確認或已完成狀態。
- **每個回合結束後更即時地重新整理 Codex 用量。** Info 面板會立即顯示本機 rollout 快照，再與即時速率額度校準；Codex 寫完最終 token 快照後還會補一次重新整理，並忽略來自舊工作階段的延遲回應。

### 介面

- **macOS 上的專案樹命中更可靠。** 虛擬列不再依賴合成器 transform，避免捲動或樹更新後 WKWebView 保留過期命中座標，導致懸停、點擊或拖曳落到另一列。

## v0.1.95 — 2026-07-21

### AI 智慧代理

- **Kimi Code 與 Zoo Code 加入工作階段樹。** VelaTerm 現在可以啟動、續接、安裝並設定這兩種代理。Kimi 使用官方 lifecycle hooks 權威回報工作、權限與等待狀態；Zoo Code 保持穩定的工作識別，並在沒有外部 hooks 時使用終端偵測。
- **即時重新整理 Codex 用量。** Info 面板可主動查詢 Codex app server 取得最新速率額度，並保留本機 rollout 快照作為相容性備援。

### 專案與終端

- **使用 `vela <path>` 開啟專案。** 發行版可安裝類似 VS Code 的 shell 指令；再次呼叫會把專案轉交既有 VelaTerm 視窗，而不會開啟重複執行個體。
- **可見且可取消的 Git 複製。** Clone Project 現在顯示 Git 階段、百分比與經過時間，可提示進度停滯，並能取消整個 Git 程序樹且不留下未完成目錄。畫面錯誤與稽核記錄會隱藏憑證及查詢 token。
- **Windows 上的 WSL 終端。** 所有已安裝的 WSL 發行版都會被偵測，並與 PowerShell、cmd、Git Bash 一起供一般終端選擇。代理工作階段仍使用 Windows 主機 shell，以確保 hooks 與執行檔路徑可靠。

### 介面與可靠性

- **更清楚的背景工作階段控制。** 背景分頁選單會顯示每個工作階段的即時狀態，超限對話框也可一次結束多個已選分頁。
- **更安全的應用程式生命週期與更新說明。** 結束前會確認是否停止執行中的工作階段；Codex lifecycle 的精確身分優先於模糊的 rollout 掃描；自動更新說明支援所有內建介面語言。

## v0.1.94 — 2026-07-12

### 本地化

- **越南語介面。** 現在可以在語言選擇器中選擇 Tiếng Việt，使用越南語系統地區設定時也會自動選取。

### 瀏覽器

- **內建瀏覽器啟動更快。** 現在，每個瀏覽器分頁都提供一鍵開啟 ChatGPT、Claude、Gemini 和 Google 的捷徑。專案和群組的內容選單也可以直接在工作階段樹的相應位置建立固定瀏覽器頁面。

### 圖片和文件

- **在 macOS 上可靠地貼上圖片路徑。** 當 WebKit 沒有將複製的圖片公開為檔案時，VelaTerm 現在會從系統剪貼簿讀取圖片，並仍將其作為檔案路徑上傳，而不會無聲地退回代理程式原生的圖片預留位置。遠端視窗會一律顯示圖片貼上設定、說明為何必須使用檔案路徑模式，並停用無法使用的原生選項。
- **將圖片貼到原始碼文件。** 原始碼編輯器現在支援貼上剪貼簿圖片。已儲存的 Markdown 文件會把圖片放在文件旁的 `assets/` 目錄中，並插入可攜式 Markdown 圖片語法；未儲存的草稿則會嵌入圖片資料，避免清除暫存檔時遺失。

### 介面

- **內容選單保持可見並準確對準項目。** 在右側邊緣附近開啟的選單會被正確測量和調整位置。對樹狀節點按右鍵時，現在只會醒目提示選單目標而不改變既有選取；群組選單也包含作用於該群組的終端機。
- **更清爽的編輯效果和狀態標籤。** 原始碼文字不再為 HTML 註解等字元序列顯示箭頭狀字型連字；用量百分比會明確標示為已使用；宿主 WebView 無關的原生內容選單也不會再出現在 VelaTerm 自有選單後方。

### 修正

- **Codex 保持在一般終端機歷程中。** 由 VelaTerm 啟動的 Codex 工作階段現在使用行內終端機模式，因此按 Esc 中斷或返回時，不會再切換終端機畫面緩衝區並讓回捲檢視跳到頂端。使用者自己的 Codex 設定不會被修改。
